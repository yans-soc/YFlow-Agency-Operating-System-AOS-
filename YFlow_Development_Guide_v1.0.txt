YFLOW DEVELOPMENT GUIDE v1.0

1.  ENGINEERING PRINCIPLES

-   Clean Architecture
-   SOLID
-   DRY
-   KISS
-   YAGNI
-   Domain Driven Design
-   Feature First
-   Testable Code

2.  REPOSITORY STRUCTURE backend/ frontend/ docs/ docker/ scripts/
    .github/

3.  GIT WORKFLOW main develop feature/ fix/ hotfix/ release/

Commit: feat: fix: refactor: docs: test: chore:

4.  CODING STANDARDS Meaningful naming Single Responsibility Dependency
    Injection No duplicated logic No business logic in
    controllers/components

5.  BACKEND RULES Controllers <50 lines Services contain business logic
    Repositories handle persistence Validation via FormRequest Policies
    for authorization Queued long-running jobs

6.  FRONTEND RULES Feature-based folders Reusable components No API
    calls directly in UI Typed interfaces Server state with TanStack
    Query Client state with Zustand

7.  DATABASE RULES UUID PK Foreign keys Indexes on FK/search columns
    Soft delete Audit timestamps No nullable unless justified

8.  API RULES RESTful Versioned /api/v1 Consistent JSON envelope Proper
    HTTP status codes Idempotent where applicable

9.  SECURITY Input validation Output escaping Rate limiting
    Authorization checks Secret management via env No secrets committed

10. TESTING Backend: Unit >80% Feature tests API tests

Frontend: Component tests E2E tests Visual regression optional

11. PERFORMANCE Lazy loading Pagination Database indexes Caching Queue
    background tasks Image optimization

12. OBSERVABILITY Structured logs Request IDs Error tracking Metrics
    Health endpoints

13. CI/CD Lint Format Static analysis Run tests Build artifacts Deploy
    staging Deploy production Rollback strategy

14. CODE REVIEW CHECKLIST Architecture respected Naming consistent Tests
    added Performance acceptable Security reviewed Documentation updated

15. RELEASE PROCESS Develop QA Staging UAT Production Post-release
    monitoring

16. DOCUMENTATION Every feature includes: Purpose Architecture API DB
    changes Migration Tests Changelog

17. AI CODING RULES AI must:

-   Follow project architecture.
-   Never invent tables/APIs.
-   Reuse components.
-   Keep files small.
-   Avoid unnecessary abstractions.
-   Add tests for new business logic.
-   Respect naming conventions.
-   Never modify unrelated files.

18. DEFINITION OF DONE Code complete Tests passing Reviewed Documented
    Performance checked Security checked Merged Deployable
