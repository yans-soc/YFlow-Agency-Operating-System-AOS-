# 04 — Domain Model Volume 1: Core Business Domain

---

## Purpose

Defines every business entity, ownership relationships, attributes, lifecycle overview, and responsibilities for the YFlow system.

---

## Domain Philosophy

**Layered Architecture:**
1. Workspace Layer
2. Organization Layer
3. Identity Layer
4. Permission Layer
5. Project Layer
6. Collaboration Layer

---

## Core Entities

### 1. WORKSPACE

**Purpose:** Root container for all organizational data.

**Owns:**
- Departments
- Teams
- People
- Projects
- Templates
- Workflow Library
- Settings

**Key Fields:** `id`, `name`, `slug`, `logo`, `timezone`, `status`

**Business Rules:**
- Must have at least one owner
- Cannot be deleted while active projects exist

---

### 2. DEPARTMENT

**Purpose:** Business division within workspace.

**Fields:** `id`, `workspace_id`, `name`, `description`

**Relationship:** Workspace → Departments (1:N)

---

### 3. TEAM

**Fields:** `id`, `department_id`, `name`, `lead_id`

**Relationship:** Department → Teams (1:N)

---

### 4. PERSON

**Fields:** 
- `id`
- `name`
- `email`
- `phone`
- `avatar`
- `department_id`
- `team_id`
- `position_id`
- `resource_type_id`
- `system_role_id`

**Owns:**
- Calendar events
- Activities
- Task assignments

---

### 5. POSITION

**Purpose:** Job title/role definition.

**Examples:**
- Backend Developer
- Frontend Developer
- SEO Specialist
- Project Coordinator

**Note:** Workspace customizable.

---

### 6. SKILL

**Fields:** `id`, `name`, `category`

**Relationship:** Person ↔ Skill (Many-to-Many)

---

### 7. RESOURCE TYPE

**Types:**
- Internal (employee)
- Freelancer
- Vendor
- Intern
- Client

---

### 8. SYSTEM ROLE

**Roles:**
- Super Admin
- Workspace Admin
- Operations Manager
- Project Manager
- Contributor
- Client

---

### 9. PROJECT

**Owns:**
- Overview
- Members
- Workflow
- Tasks
- Calendar
- Files
- Notes
- Activity log

**Fields:** `id`, `name`, `code`, `status`, `start_date`, `end_date`

**Relationship:** Workspace → Projects (1:N)

---

### 10. PROJECT MEMBER

**Fields:**
- Person reference
- Project reference
- Role within project

**Rule:** One person may join many projects.

---

### 11. PROJECT ROLE

**Roles:**
- Owner
- Manager
- Lead
- Contributor
- Reviewer
- Approver
- Observer
- Client

---

### 12. WORKFLOW

**Purpose:** Business process template.

**Contains:** Stages

---

### 13. STAGE

**Contains:** Tasks

**Order:** Sortable (defines workflow sequence)

---

### 14. TASK

**Contains:**
- Checklist items
- Comments
- Attachments

**Status Values:**
- Draft
- Todo
- Progress
- Review
- Done
- Archived

---

### 15. CHECKLIST

**Parent:** Task

**Purpose:** Sub-task breakdown within a task.

---

### 16. CALENDAR EVENT

**Can belong to:**
- Workspace
- Project
- Person
- Task

---

### 17. NOTE

**Belongs to:** Project

**Purpose:** Knowledge documentation.

---

### 18. FILE

**Belongs to:**
- Task
- Project
- Note

---

### 19. ACTIVITY

**Nature:** Immutable audit log

**Purpose:** Track all system actions.

---

### 20. NOTIFICATION

**Trigger:** Generated by domain events

**Purpose:** Alert users of relevant changes.

---

### 21. AI SESSION

**Stores:**
- AI conversations
- Workflow analysis results
- Generation history

---

## Relationship Map

```
Workspace
├─ Departments
│  └─ Teams
│     ─ People
├─ Projects
│  ├─ Members
│  ├─ Workflow
│  │  └─ Stages
│  │     └─ Tasks
│  │        ├─ Checklist
│  │        ├─ Comments
│  │        └─ Files
│  ├─ Notes
│  └─ Calendar Events
├─ Skills (↔ People)
─ Positions
└─ Settings
```
