# Task 3: GitHub App Integration

This document outlines the process for integrating Coolify with the `YANS-DIGITAL-KREASI` GitHub organization to enable a production-grade CI/CD workflow.

---

## 1. Integration Method

- **Decision**: A dedicated **GitHub App** is the chosen method for integration.
- **Rationale**:
  - **Enhanced Security**: GitHub Apps use fine-grained permissions, allowing access only to specific repositories and API endpoints, adhering to the principle of least privilege. This is more secure than using a personal access token (PAT) which grants broad access to a user's account.
  - **Scalability**: An App owned by the organization is not tied to an individual user account. This prevents disruptions if a user leaves the organization or their permissions change.
  - **Professionalism**: It is the official, recommended, and most professional way to integrate third-party services like Coolify with GitHub for production use.
  - **Webhook Management**: Provides a centralized and robust way to manage webhooks that trigger deployments.

## 2. Configuration Steps

The following steps are required to configure the GitHub App and integrate it with Coolify.

### 2.1. GitHub App Creation
1.  **Register a new GitHub App** under the `YANS-DIGITAL-KREASI` organization.
2.  **Name**: `YANS Coolify Platform Integrator`
3.  **Homepage URL**: `https://coolify.yansdigital.com`
4.  **Webhook URL**: This will be provided by Coolify once the integration process is initiated within the Coolify UI. The webhook must be active.
5.  **Webhook Secret**: A strong, randomly generated secret must be created and configured in both GitHub and Coolify to secure webhook payloads.

### 2.2. Permissions
The GitHub App will require the following permissions:

- **Repository Permissions**:
  - `Contents`: Read-only. To check out code.
  - `Metadata`: Read-only.
  - `Webhooks`: Read & write. To manage deployment webhooks.
  - `Commit statuses`: Read & write. To report build/deployment status back to commits/PRs.
- **Organization Permissions**:
  - `Members`: Read-only. To list organization members for user-related tasks if needed.

### 2.3. Private Key
- A private key will be generated by GitHub upon App creation.
- This key must be securely stored in the Coolify instance to authenticate as the GitHub App.

### 2.4. Installation
1.  **Install the App** on the `YANS-DIGITAL-KREASI` organization.
2.  **Repository Access**: Grant the App access to **All Repositories**. This ensures that any new application repository created in the future is automatically accessible by the deployment platform without manual reconfiguration.

## 3. Pre-flight Check

Before creating the App, an audit of the GitHub organization's settings is required to ensure that:
- Third-party application installations are not overly restricted.
- The user performing the setup has the necessary administrative privileges (Organization Owner).

This will be performed by the `audit-github-org.sh` script.

## 4. Coolify Configuration
- Within the Coolify UI, navigate to the GitHub App integration section.
- Provide the `App ID`, `Client ID`, `Client Secret`, `Private Key`, and `Webhook Secret` obtained from the GitHub App settings.
- Coolify will then provide the final `Webhook URL` to be saved back into the GitHub App configuration.
