# Secrets, Backup, Restore & Disaster Recovery — YANS DIGITAL Platform (Task 12)

> Operational runbooks for secrets management, backups, restore, and DR across
> VPS1 (app) and VPS2 (data).

---

## 1. Secrets management

### Where secrets live
| Secret type | Storage | Never |
|-------------|---------|-------|
| App runtime (DB pass, APP_KEY, mail, API keys) | Coolify → resource env (encrypted) | in git |
| Deploy triggers (Coolify webhook/token) | GitHub repo/org secrets | in git |
| GitHub App private key | Coolify (generated by GitHub) | in git |
| DB/Redis passwords | Coolify env + VPS2 config | in git |

### Rules
- One `.env.example` documents *keys only* (placeholders). Real values only in Coolify.
- Per-app DB user + password (`<app>_prod`), never shared root.
- `APP_KEY` unique per app; generate with `php artisan key:generate`.
- Rotation: quarterly, and immediately on suspected exposure or member offboarding.

### Rotation procedure
```
1. Generate new secret (DB pass / API key / APP_KEY).
2. Update value in Coolify resource env.
3. Redeploy app (picks up new env).
4. Revoke old credential at the source (DB user, provider).
5. Verify /api/health green.
```

## 2. Backup strategy

### What to back up
| Asset | Location | Method | Frequency | Retention |
|-------|----------|--------|-----------|-----------|
| MariaDB (all app schemas) | VPS2 | `mariadb-dump` per DB → gzip | daily + pre-deploy | 14 daily, 8 weekly |
| Redis (if persistence needed) | VPS2 | RDB snapshot copy | daily | 7 days |
| Coolify config/state | VPS1 | Coolify built-in backup / volume snapshot | daily | 14 days |
| Object storage (future) | VPS2 | provider snapshot / rsync | daily | 30 days |
| Repos | GitHub | GitHub is source of truth (+ optional mirror) | on push | ∞ |

### DB backup script (VPS2, cron)
```bash
#!/usr/bin/env bash
# /opt/backup/db-backup.sh  (cron: 0 2 * * *)
set -euo pipefail
DEST=/opt/backup/mariadb; mkdir -p "$DEST"
STAMP=$(date +%F)
for DB in $(mariadb -N -e "SHOW DATABASES" | grep -Ev '^(information_schema|performance_schema|mysql|sys)$'); do
  mariadb-dump --single-transaction --quick "$DB" | gzip > "$DEST/${DB}_${STAMP}.sql.gz"
done
# prune >14 days
find "$DEST" -name '*.sql.gz' -mtime +14 -delete
# optional: push offsite (S3/rclone)
# rclone copy "$DEST" remote:yd-db-backups/$STAMP
```

### Backup hygiene
```
[ ] Backups stored OFF VPS2 too (offsite bucket) — survive node loss
[ ] Encrypt offsite backups
[ ] Monthly restore test (see §3) — a backup is only real if it restores
[ ] Monitor backup job success (alert on failure)
```

## 3. Restore strategy

### Restore one app's database
```bash
# On VPS2 (or via Tailscale):
gunzip < /opt/backup/mariadb/yflow_prod_2026-07-27.sql.gz \
  | mariadb yflow_prod
# Then redeploy app so caches/config are fresh; verify /api/health.
```

### Point-in-time / full DB host restore
1. Provision MariaDB on replacement VPS2.
2. Restore latest dumps for all schemas.
3. Recreate app DB users + grants (least privilege).
4. Update Coolify DB host if IP changed (Tailscale).
5. Redeploy apps; verify health.

### Restore test (monthly)
```
[ ] Pick one DB, restore into a scratch schema
[ ] Run app smoke test against it
[ ] Record restore time (RTO evidence)
```

## 4. Disaster Recovery (DR)

### RPO / RTO targets
| Metric | Target |
|--------|--------|
| RPO (data loss) | ≤ 24h (daily backup); ≤ 1h if binlog/offsite streaming added |
| RTO (time to recover) | ≤ 4h for full platform rebuild |

### Failure scenarios & response
| Scenario | Response |
|----------|----------|
| **VPS1 lost (app node)** | Provision new VPS1, reinstall Coolify, restore Coolify config, reconnect GitHub App, redeploy all apps from GitHub. Data intact on VPS2. |
| **VPS2 lost (data node)** | Provision new VPS2, install MariaDB/Redis, restore from latest (offsite) backups, repoint Coolify DB host, redeploy. |
| **Both lost** | Rebuild VPS2 first (data), then VPS1 (apps). GitHub holds all source; backups hold data. |
| **Bad deploy** | Coolify rollback to previous image (see `09-deployment-cicd.md`). |
| **Corrupt migration** | Restore affected DB from pre-deploy backup + redeploy prior tag. |
| **Cloudflare/DNS issue** | Re-add records: `host`, `coolify`, `db`, `*.apps` → VPS1; verify SSL. |
| **Secret leak** | Rotate all affected secrets (§1), revoke, redeploy. |

### DR rebuild order (both nodes lost)
```
1. Restore Tailscale network (both nodes rejoin).
2. VPS2: install MariaDB + Redis → restore backups → recreate users/grants.
3. VPS1: install Docker + Coolify → restore Coolify config.
4. Reconnect Coolify GitHub App (org).
5. Recreate DNS/Cloudflare records; issue wildcard cert.
6. Redeploy every app from GitHub main; verify /api/health each.
7. Run restore smoke tests; announce recovery.
```

### DR readiness checklist
```
[ ] Offsite, encrypted DB backups exist and are current
[ ] Coolify config backed up
[ ] This runbook + credentials access documented (in a vault, not git)
[ ] Tailscale re-join keys available
[ ] DR drill performed at least annually
```
