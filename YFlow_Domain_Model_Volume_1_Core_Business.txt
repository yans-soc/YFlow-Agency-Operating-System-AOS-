YFLOW DOMAIN MODEL VOLUME 1 - CORE BUSINESS DOMAIN
=====================================

PURPOSE

Defines every business entity, ownership, relationships, attributes,
lifecycle overview, and responsibilities.

DOMAIN PHILOSOPHY

Layers: 1. Workspace 2. Organization 3. Identity 4. Permission 5.
Project 6. Collaboration

CORE ENTITIES

1.  WORKSPACE Purpose:

-   Root container. Owns:
-   Departments
-   Teams
-   People
-   Projects
-   Templates
-   Workflow Library
-   Settings

Key Fields: id,name,slug,logo,timezone,status

Business Rules: - One owner minimum. - Cannot delete while active
projects exist.

------------------------------------------------------------------------

2.  DEPARTMENT Purpose: Business division.

Fields: id,workspace_id,name,description

Relationship: Workspace -> Departments (1:N)

------------------------------------------------------------------------

3.  TEAM

Fields: id,department_id,name,lead_id

Relationship: Department -> Teams

------------------------------------------------------------------------

4.  PERSON

Fields: id,name,email,phone,avatar, department_id,team_id,
position_id,resource_type_id, system_role_id

Owns: - Calendar - Activities - Assignments

------------------------------------------------------------------------

5.  POSITION

Examples: Backend Developer Frontend Developer SEO Specialist Project
Coordinator

Workspace customizable.

------------------------------------------------------------------------

6.  SKILL

Fields: id,name,category

Many-to-many: Person <-> Skill

------------------------------------------------------------------------

7.  RESOURCE TYPE

Internal Freelancer Vendor Intern Client

------------------------------------------------------------------------

8.  SYSTEM ROLE

Super Admin Workspace Admin Operations Manager Project Manager
Contributor Client

------------------------------------------------------------------------

9.  PROJECT

Owns: Overview Members Workflow Tasks Calendar Files Notes Activity

Fields: id,name,code,status,start_date,end_date

Relationship: Workspace -> Projects

------------------------------------------------------------------------

10. PROJECT MEMBER

Person Project Role

One person may join many projects.

------------------------------------------------------------------------

11. PROJECT ROLE

Owner Manager Lead Contributor Reviewer Approver Observer Client

------------------------------------------------------------------------

12. WORKFLOW

Purpose: Business process template.

Contains: Stages

------------------------------------------------------------------------

13. STAGE

Contains: Tasks

Order: Sortable

------------------------------------------------------------------------

14. TASK

Contains: Checklist Comments Attachments

Status: Draft Todo Progress Review Done Archived

------------------------------------------------------------------------

15. CHECKLIST

Child of Task.

------------------------------------------------------------------------

16. CALENDAR EVENT

Can belong to: Workspace Project Person Task

------------------------------------------------------------------------

17. NOTE

Belongs to: Project

------------------------------------------------------------------------

18. FILE

Belongs to: Task Project Note

------------------------------------------------------------------------

19. ACTIVITY

Immutable audit log.

------------------------------------------------------------------------

20. NOTIFICATION

Generated by domain events.

------------------------------------------------------------------------

21. AI SESSION

Stores AI conversations and workflow analysis.
